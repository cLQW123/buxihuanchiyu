# 按初赛报告复现完整流程

本流程使用锁定的公开源码和公开Release依赖包，从新的工程目录创建独立Python环境，重建全部参赛原生库和九齿算子，再生成一份原版官方参考和seed42、43两份完整参赛输出。模型输入只读使用比赛统一提供的Base FL2VA Diffusers checkpoint。当前执行版本为`db19655d6a800046c3e534ef40cedfcd16cafb7b`。

联网准备端需要Git、Bash和Python 3.11.4或更新版本（支持tarfile.data_filter），且`python`命令指向该解释器；此处只下载和解包，不安装Linux wheel。离线执行端需要已分配的独占八卡Linux x86_64（glibc至少2.28）海光gfx936节点，每卡64 GiB，CPython 3.11（含pip、venv和开发头文件）、比赛厂商Torch `2.9.0+das.opt1.dtk2604`、DTK 26.04、匹配驱动和GCC 11.4.0及binutils工具（readelf）。73个wheel、完整厂商Triton和xmake由Release提供。不得用公共CUDA Torch替换厂商Torch。本次Slurm分配为单节点128 CPU、486G主机内存及8卡；复现应使用赛事统一的同等资源配置，并预留源码构建和模型存储空间。

随包xmake 3.1.2使用基础系统的`libatomic.so.1`、`libreadline.so.7`、`libncurses.so.6`、`libtinfo.so.6`和`libstdc++.so.6`。在赛事提供的其他基础镜像中，也可将`XMAKE_RUNTIME`设置为该环境兼容的xmake 3.1.2完整安装树，目录下需有`bin/xmake`和`share/xmake`。

## 在联网机器准备

```bash
set -euo pipefail
python - <<'PY'
import sys, tarfile
assert sys.version_info >= (3, 11, 4)
assert hasattr(tarfile, 'data_filter')
PY
git clone https://github.com/cLQW123/buxihuanchiyu.git
cd buxihuanchiyu
git checkout db19655d6a800046c3e534ef40cedfcd16cafb7b
bash scripts/prepare_sources.sh
if ! python scripts/fetch_dependencies.py; then
  python - <<'PYFETCH'
import json, shutil, urllib.request
from pathlib import Path
m = json.loads(
    Path('dependencies/artifacts.json').read_text())
a = Path('inputs/archives')
a.mkdir(parents=True, exist_ok=True)
u = 'https://github.com/' + m['repository']
u += '/releases/download/' + m['release_tag'] + '/'
def fetch(item):
    r = urllib.request.Request(u + item['file'],
        headers={'User-Agent': 'sgcup-offline'})
    with urllib.request.urlopen(r, timeout=60) as src:
        with (a/item['file']).open('wb') as dst:
            shutil.copyfileobj(src, dst, 4*1024*1024)
list(map(fetch, m['artifacts']))
PYFETCH
  python scripts/fetch_dependencies.py --offline
fi
```

必须保留已初始化的全部必需子模块目录、`SOURCE_PROVENANCE.json`和`inputs/`。成功准备会打印`EXACT_GIT_CHECKOUT_SOURCE_VERIFIED`及`OFFLINE_DEPENDENCIES_PREPARED 73 394`。下载脚本验证三个公开依赖资产和所有wheel的SHA256，准备`inputs/wheelhouse`、`inputs/vendor-triton`、`inputs/vendor-xmake`。不要在下载机器上用pip安装这些Linux wheel。若GitHub公共API限流，代码块会自动改用Release公开直链，随后由原下载脚本以离线模式核对完整SHA256和依赖内容。

统一首帧可以直接使用赛方提供的原始文件。若需要从本报告或官方报告模板提取，执行以下命令，`REPORT_DOCX`指向原始DOCX文件；不要截图或重新编码图片。


在源码目录的上一级打包已准备好的工程，包含隐藏的Git目录和已初始化的必需子模块；不包含任何旧构建产物。`inputs/archives`只是下载原包缓存，已解包的依赖目录仍会随工程保留。

通过赛事平台上传或scp将此tar传到计算节点可读的位置。计算节点没有公网或DNS时，不要在节点重复执行GitHub拉取和下载步骤。固定模型权重不放入tar，由赛事环境另外提供；需要配套Diffusers目录，其下包含`model_index.json`、`text_encoder`、`transformer`、`vae`、`audio_vae`、`scheduler`和`audio_scheduler`等。原始FL2VA checkpoint目录不能直接作为这里的`MODEL_PATH`。

## 在离线八卡节点执行

下列`/path/to/...`只表示赛事环境中的基础工具、输入和存储位置。先替换路径，再顺序执行同一个代码块。工程目录必须是新的，不能复制旧`build/`、`outputs/`或九齿/Triton缓存。

```bash
set -euo pipefail
export RUN_ROOT="/path/to/new-run-directory"
test ! -e "$RUN_ROOT"
mkdir -p "$RUN_ROOT"
tar -xf "/path/to/buxihuanchiyu-source-and-inputs.tar" \
  -C "$RUN_ROOT"
cd "$RUN_ROOT/buxihuanchiyu"
export COMPETITION_PYTHON="/path/to/competition/python3.11"
export VENDOR_TORCH_SITE="/path/to/vendor/site-packages"
export DTK_ROOT="/path/to/dtk"
export GCC_ROOT="/path/to/gcc"
export XMAKE_RUNTIME="$PWD/inputs/vendor-xmake"
"$XMAKE_RUNTIME/bin/xmake" --version
export MODEL_PATH="/path/to/MiniMax-H3/diffusers"
export FIRST_FRAME="$PWD/inputs/competition-first-frame.png"
unset PYTHONPATH
export PYTHONNOUSERSITE=1
"$COMPETITION_PYTHON" scripts/setup_offline.py \
  --wheelhouse "$PWD/inputs/wheelhouse" \
  --vendor-torch-site "$VENDOR_TORCH_SITE" \
  --vendor-triton-site "$PWD/inputs/vendor-triton" \
  --dtk-root "$DTK_ROOT" \
  --gcc-root "$GCC_ROOT" \
  --xmake-root "$XMAKE_RUNTIME"
unset REFERENCE_VIDEO REFERENCE_PROVENANCE
bash reproduce/validate_offline.sh
```

`VENDOR_TORCH_SITE`是统一基础环境中包含`torch/`及其dist-info的site-packages目录，不是torch/lib。`DTK_ROOT`必须包含`env.sh`，`GCC_ROOT`必须包含`bin/gcc`和`bin/g++`。脚本显式链接厂商Torch，其他Python包从离线wheelhouse安装，venv不继承系统site-packages。运行入口自动激活`build/activate.sh`并使用独立缓存，不需要另外手动安装第三方Python包或复制旧原生库。

主入口顺序执行：环境和来源检查、源码构建、6项RoPE与4项Qwen RMSNorm、88项八卡原生分发和232项辅助计算对照、原版`--legacy`参考生成、seed42/43两例连续生成、官方比较和两例严格音视频检查。固定配置为`A dog falls asleep`、8卡、124帧、50个调度点及默认768×928尺寸；50个调度点含终止零点，实际执行49次H3更新。首次源码构建和冷编译需要较长时间，应等待命令退出，不能看到视频文件就提前终止。

## 检查完成状态

```bash
"$COMPETITION_PYTHON" - <<'PY'
import json
from pathlib import Path
p = Path('outputs/offline-validation')
r = json.loads((p/'validation.json').read_text())
assert r['technical_validation_pass'] is True
assert r['reference_code_unchanged'] is True
assert r['reference_kind'] == (
    'official-unmodified-execution')
assert all(s['exit'] == 0 for s in r['stages'])
assert [c['seed'] for c in r['cases']] == [42, 43]
assert all(c['exit'] == 0 for c in r['cases'])
for name in ['media.json', 'media-seed43.json']:
    assert json.loads((p/name).read_text())['pass'] is True
print('完整复现完成，平均SSIM百分比:', r['ssim_percent'])
PY
```

原始日志位于`outputs/offline-validation/`：`build.log`、`stages.jsonl`、`official-reference/generation.log`、`continuous/cases.json`、两例各自的`generation.log`、`comparison.log`和两份媒体检查JSON。seed42输出为`continuous/case-00-seed-42/generated.mp4`，seed43输出为`continuous/case-01-seed-43/generated.mp4`。`validation.json`只在全部阶段成功后生成。失败时检查对应阶段的`.exit`和`.log`并保留现场；重试使用新的源码/运行目录，为每次运行保留独立结果。

生成文件哈希、耗时及SSIM是本次记录值，不作为其他硬件环境逐字节相同的承诺。赛题允许合理的浮点差异；正式接受和成绩由赛事方统一评测确定。
