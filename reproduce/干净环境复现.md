# 干净环境复现

目标环境为赛事提供的独占八卡Hygon gfx936节点、CPython 3.11和匹配的厂商DTK／Torch／Triton。完整执行包含源码重建、原生算子验证、seed42与seed43两个连续完整FL2VA用例、原版比较脚本和严格音视频规格检查。构建产物、Python环境和九齿／Triton缓存均来自新的工程目录。

本次部署流程还在验证，不能将该说明当作已通过初赛的证明。尤其需要区分赛方标准参考与本地兼容参考：后者只能证明技术对比完成，不能自动证明“禁止修改基线代码”要求已经满足。

## 准备源码和离线包

在可联网环境使用`prepare_sources.sh`初始化锁定的公开组件及必需的头文件子模块。`prepare_published.py`可从确切公开commit导出完整源码包，输出包含每个源码文件哈希的`SOURCE_PROVENANCE.json`。在待验证版本尚未公开时，可从本地提交导出相同结构进行预验证；必须保留这种来源差别。

源码包应解压到新的工程目录，不复制build、outputs、旧原生扩展或旧缓存。另行解压与`offline-lock.json`一致的wheel包，显式提供统一模型、首帧和参考输出路径。

## 创建独立环境

以下路径是参数示例，需要替换成当前赛事环境中的实际路径。厂商包目录只用作已申明的基础运行时来源，不是旧模型代码目录。

```bash
/path/to/competition/python3.11 scripts/setup_offline.py \
  --wheelhouse /path/to/offline/wheelhouse \
  --vendor-torch-site /path/to/vendor/site-packages \
  --vendor-triton-site /path/to/vendor-triton/site-packages \
  --dtk-root /path/to/dtk \
  --gcc-root /path/to/gcc \
  --xmake-root /path/to/xmake-install
source build/activate.sh
```

首次创建必须使用新目录。脚本不会覆盖已有venv；会在缺包、版本或哈希不符时直接报错，并生成`build/offline-environment.json`记录实际依赖来源。

## 连续生成与对比

参考来源JSON必须包括`kind`、`description`和`video_sha256`。`kind`为`organizer-standard`时应确有可核验的赛方标准输出来源；本地精度兼容修复所得参考必须标记为`compatibility-reference`，不能仅改变标记冒充赛方标准。

```bash
export MODEL_PATH=/path/to/MiniMax-H3/diffusers
export FIRST_FRAME=/path/to/competition-first-frame.png
export REFERENCE_VIDEO=/path/to/reference.mp4
export REFERENCE_PROVENANCE=/path/to/reference-provenance.json
bash reproduce/validate_offline.sh
```

统一生成配置为文本`A dog falls asleep`、124帧、50个调度点、原默认分辨率和八张卡。50个调度点包含终止零点，按官方语义执行49次模型更新。两个用例分别使用seed42、43，各自重新计算，不复用历史生成结果。运行日志、进程PID、退出码、配置、耗时、文件哈希和对比结果写入`outputs/offline-validation/`。

`validation.json`的`technical_validation_pass`只表示这一构建运行和比较流程通过；不等价于赛方最终接受、数值实现边界已全部审计或本地兼容基线获准。最终提交报告必须结合全部要求和真实参考来源判断。
