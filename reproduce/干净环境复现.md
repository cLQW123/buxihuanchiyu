## 准备源码和离线包

在可联网环境使用`prepare_sources.sh`初始化锁定的公开组件及必需的头文件子模块，并生成包含源码哈希的`SOURCE_PROVENANCE.json`。执行`python scripts/fetch_dependencies.py`获取锁定的73个wheel、完整厂商Triton包和实测xmake工具；文件较大，通过GitHub Release提供，哈希固定在仓库内。也可使用`--archive-dir /path/to/assets --offline`校验已有下载。`prepare_published.py`可从确切公开commit导出完整源码包。在待验证版本尚未公开时，可从本地提交导出相同结构进行预验证；必须保留这种来源差别。

源码包应解压到新的工程目录，不复制build、outputs、旧原生扩展或旧缓存。另行解压与`offline-lock.json`一致的wheel包，显式提供统一模型路径；首帧由源码assets默认提供，参考输出默认重新生成。

## 创建独立环境

以下路径是参数示例，需要替换成当前赛事环境中的实际路径。厂商包目录只用作已申明的基础运行时来源，不是旧模型代码目录。

```bash
/path/to/competition/python3.11 scripts/setup_offline.py \
  --wheelhouse /path/to/offline/wheelhouse \
  --vendor-torch-site /path/to/vendor/site-packages \
  --vendor-triton-site /path/to/vendor-triton/site-packages \
  --dtk-root /path/to/dtk \
  --gcc-root /path/to/gcc \
  --xmake-root "$PWD/inputs/vendor-xmake"
source build/activate.sh
```

首次创建必须使用新目录。脚本不会覆盖已有venv；会在缺包、版本或哈希不符时直接报错，并生成`build/offline-environment.json`记录实际依赖来源。

## 连续生成与对比

默认无需提供参考视频：验证脚本在重建完成后，使用独立子进程运行原版官方`--legacy`入口，新生成同一输入、seed42、124帧、50调度点的参考视频，再连续运行参赛用例并比较。`scripts/create_reference.py`校验官方入口、比较脚本及安装的Diffusers源码哈希，不安装参赛数值适配器。若赛方已提供标准参考，可同时设置`REFERENCE_VIDEO`与`REFERENCE_PROVENANCE`跳过参考生成。

外部参考来源JSON必须包括`kind`、`description`、`video_sha256`和`first_frame_sha256`。`kind`为`organizer-standard`时应确有可核验的赛方标准输出来源；直接运行原版官方入口及官方依赖得到的结果标记为`official-unmodified-execution`，并附源码哈希、完整生成完成记录和空修改列表；本地精度兼容修复所得参考必须标记为`compatibility-reference`，不能仅改变标记冒充赛方标准。

```bash
export MODEL_PATH=/path/to/MiniMax-H3/diffusers
unset FIRST_FRAME REPORT_DOCX
unset REFERENCE_VIDEO REFERENCE_PROVENANCE
bash reproduce/validate_offline.sh
```

统一生成配置为文本`A dog falls asleep`、124帧、50个调度点、原默认分辨率和八张卡。50个调度点包含终止零点，按官方语义执行49次模型更新。两个用例分别使用seed42、43，各自重新计算，不复用历史生成结果。运行日志、进程PID、退出码、配置、耗时、文件哈希和对比结果写入`outputs/offline-validation/`。

`validation.json`的`technical_validation_pass`只表示这一构建运行和比较流程通过；不等价于赛方最终接受、数值实现边界已全部审计或本地兼容基线获准。最终提交报告必须结合全部要求和真实参考来源判断。
